## 重構目標

原始專案以「章節編號」命名資料夾，無法從名稱得知內容，且同主題練習散落多處。

重構目標是：**依功能分類、統一命名、保留完整練習、刪除重複內容。**

## 現況事實（已查證）

- 前端 Angular 19 + Angular Material 19 + SCSS
- 資料夾以章節編號命名（`ch10`、`ch17`、`ch23-24` 等），無法從名稱辨識內容
- **同主題練習散落在多個資料夾**：
  - 路由練習分散在 `route`、`route2`、`route3`、`routing`、`routing2` 五個地方
  - 表單練習分散在 `ch10`、`ch17`、`ch18`
  - HTTP 練習分散在 `@http-service`、`@interceptors`、`apitest`、`cookie`
- **同一功能有多個重複實作**：
  - `input` 與 `output` 分別示範 `@Input` 和 `@Output`，但兩者其實是同一主題
  - `login` 有兩個版本（`practice/login` 用服務，`route3/login` 用 queryParams）
  - `first`、`second`、`html`、`typescript`、`pract` 等過於簡單且重複
- 命名風格不一致（`kebab-case`、`camelCase`、`PascalCase` 混用）
- 有巢狀 `.git` 目錄（`ch10/.git`）
- 有大量空 SCSS 檔（約 17 個）
- 殘留 `console.log` 除錯訊息（約 10+ 處）

## 已決定的決策

| #   | 決策                                     | 理由                                                |
| :-- | :--------------------------------------- | :-------------------------------------------------- |
| 1   | **資料夾從「章節編號」改成「功能分類」** | `ch10`、`ch17` 無法辨識內容，改用功能命名可一目了然 |
| 2   | **服務集中到 `core/services/`**          | 全站只載入一次的服務應集中管理                      |
| 3   | **攔截器集中到 `core/interceptors/`**    | 攔截器與服務職責不同，獨立資料夾更清晰              |
| 4   | **資料傳遞獨立為 `data-passing/`**       | `@Input`、`@Output` 與路由狀態傳遞是兩個獨立主題    |
| 5   | **`syntax/` 不連結路由**                 | 語法練習是獨立練習，不需要透過路由存取              |
| 6   | **`project/` 不動**                      | 底下是完整功能的小專案，結構已正確                  |
| 7   | **移除 `@` 前綴**                        | `@` 是 npm scope 符號，不是本地資料夾命名慣例       |
| 8   | **服務合併為單一 `services/`**           | `@services/` 與 `@http-service/` 都是服務，應合併   |
| 9   | **統一命名為 `kebab-case`**              | 業界標準，Angular 官方 style guide 建議             |
| 10  | **元件類別名稱保持 `PascalCase`**        | Angular 預期類別名稱使用 PascalCase                 |
| 11  | **刪除巢狀 `.git`**                      | 會干擾主專案的版本控制                              |
| 12  | **刪除空 SCSS 檔**                       | 0 位元組的檔案沒有意義                              |
| 13  | **移除殘留 `console.log`**               | 練習專案不該留除錯訊息                              |
| 14  | **設定路徑別名**                         | 避免相對路徑地獄（`../../../../`）                  |

## 不執行的項目（附原因）

| #   | 項目                             | 原因                               |
| :-- | :------------------------------- | :--------------------------------- |
| 1   | **不做 Barrel 檔案（index.ts）** | Angular 官方不推薦，會增加維護成本 |
| 2   | **不做 lazy-loading**            | 練習專案不需要分流載入             |
| 3   | **不抽 shared 模組**             | 規模還小，等真的重複了再抽         |
| 4   | **不改寫成 React**               | 重構與框架無關，卡住的從來不是框架 |

## 最終結構

```text
src/app/
├── core/                  # 全站只載入一次
│   ├── interceptors/      # HTTP 攔截器
│   └── services/          # 共用服務
├── routing/               # 路由練習
├── binding/               # 資料繫結
├── data-passing/          # 元件間資料傳遞（@Input / @Output、路由狀態）
├── http/                  # HTTP 與 Cookie 練習
├── angular-material/      # Angular Material 元件練習
├── syntax/                # TypeScript 語法練習（未連結路由）
└── project/               # 完整功能的小專案
```
